Provenance (reproducibility)

Run it yourself

This page is also an executable Jupyter notebook: open / download provenance.ipynb. The notebooks run end-to-end and double as part of Mera's test suite.

Six months after you make a figure, the question is always the same: which snapshot, which Mera version, what units produced this? provenance answers it. It reads the metadata every Mera result already carries (its InfoType) and returns a compact, deterministic record. You can print it, compare it in a test, or put it on a figure or into a log.

Mera keeps one record of where a result came from, at three levels:

levelthe recordpage
one objectprovenance(gas), carried in memory by every Mera resultProvenance
one filea sidecar, <file>.meta.json, next to every file Mera savesSharing Results & Sidecars
one folderbundle("."), one record of a whole analysis, for publishingSharing Results & Sidecars
One part of a larger picture

A provenance record says what produced a number. It does not, by itself, let someone rebuild the software that produced it. For that you also need the package versions pinned in a Julia project. Reproducibility collects the four pieces, the project, this record, the published formula behind each quantity, and the test simulations with known answers, and shows them working together.

# Example-data root. Point this at your own simulation folder, or set the
# MERA_EXAMPLES environment variable; every path below is built from it.
MERA_EXAMPLES = get(ENV, "MERA_EXAMPLES", "/Volumes/FASTStorage/Simulations/Mera-Tests");

using Mera
info = getinfo(300, joinpath(MERA_EXAMPLES, "RAMSES/mw_L10"))

# The loading messages add nothing on this page, so the data reads below are quiet.
gas = gethydro(info, verbose=false, show_progress=false);

The record

provenance(obj) returns a Provenance struct. Printed, it is a short block with the Mera version, the simulation and output (and the code that wrote it), the snapshot time, the box and level range, and the scale type.

p = provenance(gas)
println(p)
Provenance:
  Mera version : v1.9.0
  simulation   : /Volumes/FASTStorage/Simulations/Mera-Tests/RAMSES/mw_L10
  output       : 300  (RAMSES, written 2025-06-21T18:31:24.020)
  time         : 445.89 Myr
  box / levels : L=48.0  ndim=3  levels 6–10
  scale type   : ScalesType003

Which build ran

pkgversion reports the same version whether Mera came from the registry, from a branch installed from GitHub, or from a checkout. A result made on a development version would then look like it was made on the release. mera_build closes that gap, and its value is the version field of every record.

mera_build()
"1.9.0"

On a normal install it is just the version, as above. A branch installed from GitHub (pkg> add Mera#master) adds the branch and the content hash of the code. A git checkout adds the branch and the commit, and marks a working tree with uncommitted changes, because then the commit alone does not say what ran:

Mera v1.9.0 (repo master @ tree 62c57b9) | mw_L10/output_00300 | 445.89 Myr | ...
Mera v1.9.0 (dev master @ 3a91f2c) | mw_L10/output_00300 | 445.89 Myr | ...
Mera v1.9.0 (dev my-feature @ 4f2a9c1 +uncommitted) | mw_L10/output_00300 | 445.89 Myr | ...

This keeps a shared script honest about what produced it. The Gallery uses the same line in its attribution block, so a reader can tell a released Mera from somebody's branch.

Set MERA_PROVENANCE_PLAIN=1 to force the plain version. These pages are rendered that way, so they show a release rather than the checkout the documentation was built from.

mera_install gives the full record: how Mera was installed, the branch or commit where that applies, and whether the code is exactly the registered release.

sourceinstalled with
:registrypkg> add Mera
:repositorypkg> add Mera#master, or a URL with a branch
:checkouta git checkout, pkg> dev Mera
:patha local folder without git

registered compares the code's content hash with the one the Julia registry stores for this version: true means the code is exactly the registered release, also when it came from a branch; false means it differs or has uncommitted changes; nothing means unknown, for example when the local copy of the registry is older than the version.

mi = mera_install()
println("source     : ", mi.source)
println("registered : ", mi.registered)
source     : checkout
registered : nothing

This page is built from a checkout of the repository, so it says :checkout; on a normal installation it says :registry. Every sidecar stores this record next to the file it describes.

What it records

Every field is read from the snapshot's own metadata, plus the Mera build:

fieldmeaning
mera_versionthe Mera version number
mera_buildthe version, plus the branch and commit (git checkout) or branch and content hash (branch install)
path, outputthe simulation folder and the output number
simcodethe code that wrote the output
cosmologicaltrue for a cosmological run
time_myrsnapshot time in Myr; for a cosmological run, the age of the universe
redshift, aexpredshift and expansion factor; 0 and 1 for a normal run
boxlen, ndimbox length in code units, number of dimensions
levelmin, levelmaxthe AMR level range of the snapshot
scale_typethe version of the unit-scale struct, which matters for older saved files
file_ctimewhen the output was written
for f in fieldnames(Provenance)
    println(rpad(f, 13), "= ", repr(getfield(p, f)))
end

Cosmological runs

For a normal run the time is physical, in Myr or Gyr. For a cosmological run the record shows the redshift, with the expansion factor and the age of the universe. iscosmological tells which case you have. The galaxy above is not cosmological, so here is one of the test simulations that is. Only its metadata is read.

cinfo = getinfo(80, joinpath(MERA_EXAMPLES, "RAMSES/yt_cosmo"), verbose=false)
pc = provenance(cinfo)
println(pc)
println()
println("iscosmological : ", iscosmological(cinfo), "   (the galaxy: ", iscosmological(info), ")")
println("redshift       : ", pc.redshift)
println("aexp           : ", pc.aexp)

Stamping a figure or a log

provenance_string gives the record as one line. Put it in a figure caption, a log file or the header of a file you write. The time is in Myr or Gyr, or z=… for a cosmological run.

println(provenance_string(gas))
println(provenance_string(cinfo))
Mera v1.9.0 | mw_L10/output_00300 | 445.89 Myr | L=48.0 ndim=3 lmin=6 lmax=10 | ScalesType003
Mera v1.9.0 | yt_cosmo/output_00080 | z=0.14256 | L=1.0 ndim=3 lmin=6 lmax=16 | ScalesType003

Where it applies

provenance works on an InfoType and on every result that carries one in its .info field:

  • every data object, and any subregion of one
  • a projection map
  • a profile, phase or pdf of a data object or a map
  • a galaxy frame from face_on or edge_on

The record describes the snapshot, not the selection. A subregion, or a read of one variable up to a lower level, gives the same record as the full read.

println("InfoType   : ", provenance_string(gas.info))

sd = projection(gas, :sd, :Msol_pc2; center=[:bc], verbose=false, show_progress=false)
println("map        : ", provenance_string(sd))
println("pdf        : ", provenance_string(pdf(gas, :rho)))

parts = getparticles(info, verbose=false, show_progress=false)
println("particles  : ", provenance_string(parts))

# one variable up to level 8 is enough: the record still says levels 6 to 10
grav = getgravity(info, :epot, lmax=8, verbose=false, show_progress=false)
println("gravity    : ", provenance_string(grav))
InfoType   : Mera v1.9.0 | mw_L10/output_00300 | 445.89 Myr | L=48.0 ndim=3 lmin=6 lmax=10 | ScalesType003

A plain value cannot know its snapshot: a getvar array, a timeseries table, or a pdf of a plain array. provenance then throws an ArgumentError that says so. Take the provenance of the data object you computed it from, or, when you save such values, pass that object to exportdata as source.

rho = getvar(gas, :rho)
try
    provenance(rho)
catch err
    println(sprint(showerror, err))
end
println()
println("use the source instead : ", provenance_string(gas))
ArgumentError: provenance: this Array carries no `.info`. Apply it to a data object (hydro/particles/gravity/clumps/RT), a projection map, a profile, phase or pdf of either, a galaxy frame, or an InfoType. For a result without it (a timeseries table, a pdf of a plain array, a getvar array), take provenance of the source data object.
use the source instead : Mera v1.9.0 | mw_L10/output_00300 | 445.89 Myr | L=48.0 ndim=3 lmin=6 lmax=10 | ScalesType003

Deterministic

The record depends on the snapshot's own metadata and on the Mera build, never on the wall clock. Two independent reads of the same output give identical records, which makes the record safe to compare in a test.

# read the metadata of the same output again, from disk
p2 = provenance(getinfo(300, joinpath(MERA_EXAMPLES, "RAMSES/mw_L10"), verbose=false))
println("identical to the first read : ", p2 == p)
identical to the first read : true
